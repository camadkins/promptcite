## Chain-of-custody policy

- Adding a maintainer requires:
  1. Pull request adding the maintainer to this file, signed off by all current maintainers
  2. GitHub team membership granted on the same PR merge
- Removing a maintainer requires:
  1. A PR moving the entry to "Former maintainers" with the departure date
  2. Optional rationale in the PR description
  3. GitHub team membership revoked on the same PR merge
- Transferring project ownership requires:
  1. All conditions above
  2. Update to the `SECURITY.md` reporting address in the same PR

## Why this matters

This file is the record of who can merge and release. It is updated *in the
same PR* as any role change, so the git history is the audit trail.
